# Lab Execution Modes

*Genomics with GoliathOmics · Goliath Research Academy* · [Course syllabus](README.md)

| Mode | What runs | Needs |
|---|---|---|
| Offline | guides, notebooks (Modules 3–8, 10), `pytest` | Python only |
| Database lab | PostgreSQL 19 + official seeds (`python course_lab.py up`) | Docker |
| Portal lab | the database lab plus the GoliathApp portal in dev mode (`python course_lab.py portal`) | Docker, ~4 GB RAM |

## Security boundaries

* Every port binds to 127.0.0.1. The compose project is disposable (`python course_lab.py down`).
* `.env` holds random values generated by `course_lab.py init`; they are never printed.
* **Dev sign-in.** The portal uses GoliathApp's development sign-in
  (`GOLIATH_PLATFORM_HOST_DEV_LOGIN`) with a random secret header, as user 1 in scope 1. This is
  for a local lab only. Production deployments must never set it.
* `lab/portal_smoke.py` refuses any host other than 127.0.0.1, localhost or the compose service.
* The lab creates the `goliath_portal` login role with GoliathOmics' own
  `scripts/apply_gateway_db_roles.sh`, with the random password from `.env`, in the lab database only.
* No cloud resources, no paid services, no sequencing workers. The lab never runs alignment on a
  GPU; the modules teach those paths from configuration and public sample files.
